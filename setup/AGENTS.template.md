## Выбор скиллов для программирования

Выбирай доступные скиллы по смыслу запроса, даже если пользователь не назвал скилл. Основные ориентиры: изменение БД → сервер → клиент, схема или API — senior-fullstack; ошибка или регрессия — diagnosing-bugs; работа через тесты или интеграционные тесты — tdd; границы модулей и рефакторинг — codebase-design; предметные термины, словарь и ADR — domain-modeling; React/Next.js performance — vercel-react-best-practices; ревью изменений — code-review; описание PR — pr; настройка проверок перед коммитом — setup-pre-commit.

Если несколько скиллов пересекаются, используй skill-router. Выбирай один основной подход, добавляй специалистов только для отдельной нужной части задачи. Для UI учитывай существующие design-taste-frontend, impeccable, emil-design-eng, design-system и ui-ux-pro-max; для motion — motion, animation-performance и accessible-animation. Учитывай профильные скиллы Supabase/Vercel и точные условия запуска Codex Security. Не загружай две копии одного скилла. Не применяй скилл, если его задача не совпадает с запросом.

Сохраняй ручной запуск: policy.allow_implicit_invocation: false, disable-model-invocation: true и явные ограничения в описании запрещают автоматический выбор, в том числе через другой скилл. setup-ts-deep-modules и review-animations — только при явном вызове. Запросы написать или исправить код выполняй в режиме build; обучение — только по запросу. Выбор скилла не даёт разрешения запускать сторонние скрипты, устанавливать зависимости, менять чужие проекты, публиковать, делать commit/push/deploy или выполнять разрушительные команды. Проверяй полномочия по текущей задаче; уже полученные разрешения не запрашивай повторно. Сохраняй стек, настройки и инструкции проекта. ## Отчёты «Сделал / Делает / Дальше» в Pixel Agents

При выполнении согласованной задачи в локальном Codex передавай короткий отчёт в Pixel Agents: после выбора плана, после значимого результата или изменения плана и перед итоговым ответом. Используй `/usr/bin/python3 @@SETUP_HOME@@/.local/share/pixel-agents-codex/report.py`, передавая JSON через stdin с ровно тремя строковыми полями `done`, `current`, `next` (каждое до 280 символов, одна строка). `done` — полученный результат с оговорками проверки; `current` — выполняемая сейчас работа; `next` — ближайший план. Неизвестное оставляй пустой строкой. При завершении `current` должен быть пустым; если продолжение не запланировано, `next` тоже пустой.

Пиши краткое описание работы, без ключей, личных данных, фрагментов переписки или содержимого файлов. Передача идёт только в локальный наблюдатель. Запускай скрипт из исходной рабочей папки чата, а не из вложенной папки отдельной команды. Скрипт сам берёт идентификатор из `CODEX_THREAD_ID` и рабочую папку; не подменяй идентификатор другого агента. При делегировании включай этот способ отчёта в ограниченное задание субагента: каждый сообщает только о своей работе. Не сообщай о выполнении по одному факту вызова инструмента. Если скрипт отсутствует или отчёт не принят, продолжай основную задачу, не делай циклических повторов и не заявляй об успешной доставке. Эти отчёты не заменяют согласование новой задачи и не дают дополнительных разрешений.
